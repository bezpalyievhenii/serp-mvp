# SERP MVP — казино, Канада

Берёт топ-10 мобильной выдачи Google.ca по ключам, копит историю позиций в Google Sheets и размечает каждый сайт через Claude: подходит ли он для размещения, какие казино-бренды на нём (с цитатой-доказательством) и как связаться. Сверху — веб-интерфейс менеджера (RU/EN) и встроенное расписание.

## 1. Как запустить

Нужен Node.js 22+. Сервисный аккаунт Google за 5 шагов:
1. [console.cloud.google.com](https://console.cloud.google.com) → создать проект.
2. APIs & Services → Library → **Google Sheets API** → Enable.
3. IAM & Admin → Service Accounts → Create (роли не нужны).
4. Аккаунт → Keys → Add key → JSON. Положить файл **вне** репозитория.
5. В таблице «Настройки доступа» → добавить `…@….iam.gserviceaccount.com` как **редактора**.

```bash
git clone <repo> && cd serp-mvp && npm ci
cp .env.example .env      # ключи SearchApi и Anthropic, ID таблицы, путь к JSON
npm run doctor            # проверит всё и скажет, что исправить
npm run setup             # создаст листы, заголовки, настройки и 10 стартовых ключей
npm run run               # прогон: выдача → Sheets → разметка
npm run serve             # интерфейс: http://localhost:3000 (без ключей: -- --demo)
```
Другие команды: `npm test` (офлайн), `npm run export` (CSV + XLSX в `results/`), `npm run run -- --dry-run | --from-cache | --refresh | --no-label | --relabel`. Для сервера — системный cron: `0 7 * * * cd /opt/serp-mvp && npm run run >> run.log 2>&1`.

## 2. Инструменты и почему

- **SearchApi.io** (запасной — **HasData**, переключение `SERP_PROVIDER`): 100 бесплатных запросов без карты, мобильная выдача `gl=ca`. SerpApi не подошёл — регистрация блокирует номера телефонов. Позиции 3–10 SearchApi отдаёт токенами — код разворачивает их бесплатным Resolve API.
- **Claude** через structured outputs + zod: Haiku 5.5 для тестов (в 20 раз дешевле), Sonnet 5.5 — вариант по умолчанию; модель — одна строка `LLM_MODEL`. Бренды и `is_relevant` проверяет код, а не модель.
- **Google Sheets** — менеджер видит и правит данные без приложения; доступ только через интерфейс `Store`, поэтому БД встанет без правки ядра.
- **TypeScript strict + zod + vitest** — всё внешнее валидируется, 100 офлайн-тестов.

## 3. Стоимость прогона (из листа `Runs`, 10 ключей)

| Прогон | SERP-запросы | Разметка | Время |
|---|---|---|---|
| Первый за день (36–58 новых URL, Haiku) | 12–13 из бесплатных 100 | $0.011–0.022 | 2 мин |
| Повтор в тот же день | 0 (берётся сегодняшний снимок) | $0 | 6 с |
| Полная переразметка 67 URL (Haiku) | 0 | $0.024 | 1 мин |

На Sonnet 5.5 те же токены стоили бы ~$0.6 за первый прогон (расчёт по ценам, не замер). Лимит расходов — `max_run_cost_usd` в `Settings` (по умолчанию $2).

## 4. Что сознательно не сделал

Авторизация, Docker, деплой, MCP-сервер, несколько сотрудников, БД — только слои под них. Обход Cloudflare: 37% страниц не скачиваются и размечаются по сниппету (confidence ≤ 0.4, пометка `snippet-only`). Бонус В4 (партнёрские редиректы) — колонка `affiliate_targets` есть, логики нет. Известное: 2 moderate-уязвимости `uuid` внутри `exceljs` (наш код уязвимую функцию не вызывает).

## 5. Что сделал бы дальше

Сервер + системный cron и уведомления о `partial`; MCP-интерфейс над `src/core`; доступ для нескольких сотрудников (авторизация, роли); SQLite/Postgres вместо Sheets (новая реализация `Store`); **DataForSEO** ($0.0006 за запрос) вместо бесплатных квот для ежедневной работы; headless-браузер для страниц за Cloudflare; промпт v3 с явными признаками СМИ (см. `docs/LABEL_CHECK.md`).
